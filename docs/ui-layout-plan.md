# 화면 크기별 정보 설계 — 2026-09-23

## 목표

작은 창에서도 사용자가 가장 먼저 찾는 정보인 **한도 종류, 남은 비율, 리셋까지 남은 시간, 그래프**를 항상 함께 표시한다. 마우스를 올려야만 핵심 정보를 알 수 있게 만들지 않는다.

예: 주간 한도 / 69% 남음 / 리셋까지 5일 2시간 / 잔여량 그래프.
예시 수치는 설명용이며 실제 표시는 서버 응답으로 결정한다.

## 크기별 설계

| 화면 | 조건 | 표시 정보 |
| --- | --- | --- |
| 작게 | 높이 150 미만 | 한도명, 잔여 비율, 그래프, 남은 리셋 시간. 여백과 글자 크기만 줄임 |
| 기본 | 기본 270×160 및 확대 조건 미충족 | 핵심 정보 + 최근·다음 갱신 시각 |
| 확대 | 너비 340 이상, 높이 260 이상 | 기본 정보 + 사용한 비율, 정확한 리셋 날짜·시각, 조회 상태, 갱신 간격, 초 단위 최근·다음 갱신 시각 |

크기는 Windows의 배율이 적용되는 논리 단위이다. 최소 크기는 기존 220×130을 유지한다.
폭만 넓히거나 높이만 늘렸을 때는 상세 정보가 잘리지 않도록 확대 조건을 모두 충족할 때만 상세 모드로 전환한다. 한도 개수가 많으면 스크롤로 접근한다.

## 확대 정보의 가치

- **사용한 비율:** 잔여량과 함께 현재 소비 정도를 확인한다. 동일한 기준에서 `100 - 잔여 비율`로 계산한다.
- **정확한 리셋 시각:** 상대 시간만으로 알기 어려운 다음 작업 일정을 잡는 데 도움을 준다. PC 현지 시간으로 날짜·요일·시각을 표시한다.
- **조회 상태:** 최근 데이터인지, 조회에 실패해 이전 결과를 보고 있는지 구분한다.
- **갱신 간격과 최근·다음 갱신:** 다음 서버 조회가 언제인지 알 수 있다. 수동 새로고침 성공 시 다음 일정도 갱신한다.

## 표시 원칙

- 작은 화면에서도 한도명·비율·리셋 시간·그래프를 숨기지 않는다.
- 조회 실패나 진행 중 상태는 작은 화면에서도 표시한다. 공간이 부족하면 스크롤한다.
- 서버가 주간 한도만 제공하면 주간 한도만 표시한다. 일간 한도를 임의로 만들지 않는다.
- 리셋 날짜가 없으면 정보 없음으로 표시한다. 리셋 시각이 지나도 잔여량을 임의로 복구하지 않는다.
- 사용 이력을 저장하지 않는 현재 버전에서 소비 속도, 소진 예상 시각, 일별 증감 그래프는 만들지 않는다. 이력 수집·보관 기준을 정한 후 별도 기능으로 검토한다.

## 확인 항목

최소, 기본, 확대, 확대 경계, 좁고 긴 창, 넓고 낮은 창, 다시 줄인 창에서 핵심 항목이 유지되는지 확인한다. 두 한도는 각 기준 크기에서 스크롤 없이 표시하고, 주간 한도만 있는 계정에 일간 한도를 추가하지 않는다. 확대 화면의 조회 실패 표시도 확인한다.
