# 세로형 대시보드와 서비스 확장

## 이번 범위

최소 너비에서도 높이에 따라 정보를 확장한다. Codex 핵심 정보는 상단에 유지하고 이메일, 다른 AI 사용량을 먼저 제공한다. 첫 공급자는 Gmail과 Claude Code로 정한다. Spotify, Gemini, Outlook, 메일 전송, 여러 계정 동시 조회는 후속 범위다.

## 표시 규칙

- 높이 150 미만: 기존 핵심 한도 정보와 최소 여백 유지.
- 높이 150~259: 기존 기본 화면 유지.
- 높이 260 이상: 너비와 관계없이 Codex 상세 정보를 줄바꿈하여 표시.
- 높이 360 이상: Codex·Gmail·Claude 좌우 전환을 기본으로 제공. 세로 모두 보기로 바꿀 수 있다.
- 좌우 버튼으로 선택하고 앞으로·뒤로로 순서를 바꾼다. 선택·순서·보기 방식은 저장한다. 메인 연결 버튼은 없으며 환경설정에서 연결한다.
- 카드가 넘치면 추가 정보 영역을 스크롤. 메일 제목은 최대 두 줄과 툴팁, 긴 발신자는 말줄임·툴팁 사용.
- 넓은 창에서도 동일한 순서를 유지하고 글자 크기를 적당히 확대. 연결 전에는 연결 방법을 표시하고 예시 데이터를 실제 값처럼 채우지 않는다.

## 데이터와 갱신

GmailClient는 인증과 메타데이터 API를 담당하고 ClaudeBridge는 공식 상태 표시줄의 입력 중 한도만 수신한다. 화면은 MailSnapshot/ClaudeSnapshot을 렌더링한다. 공급자 실패를 분리하고 분 단위 갱신 설정은 공유한다. F5는 각 공급자를 갱신하며 이미 실행 중인 동일 공급자 요청은 중복하지 않는다.

Gmail은 받은편지함의 정확한 미확인 메시지 수와 최신 3개 제목·발신자만 제공한다. Claude는 마지막 전달 시각과 이전 값 여부를 표시하며 새로고침이 서버 조회라는 인상을 주지 않는다. 한도가 없으면 미제공 상태로 표시한다.

## 다음 확장

1. 공급자별 숨김. 카드 순서 변경은 구현 완료.
2. 다른 이메일 공급자의 공식 OAuth와 읽기 전용 API.
3. Windows 미디어 세션을 이용한 현재 곡·재생 제어, 이후 Spotify 플레이리스트.
4. Gemini 구독 한도는 공식 외부 조회 경로를 확인한 뒤 추가. API 비용을 구독 잔여량으로 대체하지 않는다.

## 검증 경계

가상 데이터로 크기 전환·스크롤·오류·미연결 UI를 검사하고, HTTP 모형으로 Gmail 요청/응답, 실제 Windows DPAPI, Claude JSON의 누락 필드와 최소 데이터 저장, OAuth state/거절 응답을 검사한다. 실제 Google 동의·토큰 갱신과 Claude Code에서 첫 한도가 전달되는 전체 흐름은 사용자의 계정 연결 후 확인해야 한다.
